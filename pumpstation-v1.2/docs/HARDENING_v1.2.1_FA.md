## ۳-۱) نسخه ۱.۳ — فاز ۳ کامل شد

| موضوع | چه اضافه شد |
|---|---|
| نشست | جدول `sessions` سروری، فهرست دستگاه‌ها، بستن یک دستگاه، «خروج از سایر دستگاه‌ها» |
| قفل ورود | ذخیره در دیتابیس (`auth_locks`) + رفع قفل توسط ادمین (`admin.unlock`) |
| ثبت خطا | `app_events` + `onRequestError` + شناسهٔ درخواست در همهٔ پاسخ‌های خطا |
| ثبت تکراری | `Idempotency-Key` و صف آفلاین مرورگر با همان کلید |
| CSRF | بررسی Origin/Sec-Fetch-Site در میدل‌ور |
| کارایی | ETag/304 برای `/api/state`، ایندکس‌های تکمیلی، بایگانی داده‌های قدیمی |
| داده | نمای ترکیبی جاری+بایگانی، خروجی CSV، سطل بازیافت تجهیزات، VACUUM از پنل |
| فاجعه | `scripts/doctor.mjs` (تشخیص/بازیابی)، قفل پوشهٔ داده، خاموشی تمیز، بازنشانی اضطراری PIN |
| پایش | `/api/health?full=1` با دیسک، حجم دیتابیس، سن بک‌آپ، نشست‌ها، صف، خطاها |
| امنیت دفتر | زنجیرهٔ هش روی `activity` و بازبینی یک‌کلیکی |

## ۴) آنچه باقی مانده (پیشنهادی برای فاز بعد)

1. صفحه‌بندی هشدارها/فعالیت‌ها و آرشیو سالانهٔ داده‌های قدیمی (برای چند سال کارکرد).
2. نمایش وضعیت صف ارسال در رابط کاربری + تلاش مجدد خودکار با سقف.
3. سطل بازیافت برای تجهیزات حذف‌شده (کاتالوگ انجام شد).
4. کارت «امنیت» در تب ادمین: فهرست آخرین ورودها، خطاها، بک‌آپ‌های فایلی، دکمهٔ خروج از همهٔ دستگاه‌ها (اکشن‌های سرور آماده است، فقط رابط کاربری مانده).
5. فرم کاغذی گزارش روزانه (بند ۸-۱ سند مادر) که منتظر فایل شماست.

## ۵) متغیرهای محیطی جدید

| متغیر | پیش‌فرض | کاربرد |

| `BACKUP_DIR` | `.data/backups` | مسیر بک‌آپ‌های JSON (بهتر: درایو دیگر) |
