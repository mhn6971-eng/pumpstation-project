## نسخه 1.4.11 — بازطراحی نصب npm و تشخیص خطا (۱۴۰۵/۰۸/۱۶)

- ساختار npm از مسیر تودرتوی `runtime\npm\package\bin` به مسیر ساده‌تر `runtime\npm\bin` تغییر کرد؛ محتویات خود بستهٔ npm مستقیماً به پوشهٔ runtime کپی و وجود فایل CLI به‌صورت `Leaf` بررسی می‌شود.
- اجرای نسخهٔ Node و npm دیگر روی خروجی null متد `Trim()` صدا نمی‌زند؛ کد خروجی، متن خطا و مسیر CLI در گزارش نصب نمایش داده می‌شود.
- نسخهٔ نصاب در ابتدای اجرا چاپ می‌شود تا اجرای ZIP قدیمی از نسخهٔ تازه قابل تشخیص باشد.
- launcher و PATH با ساختار جدید npm هماهنگ شدند؛ Node سالمِ موجود حفظ می‌شود و npm به‌تنهایی ترمیم می‌شود.
- تست نصب تازه برنامه ۲۹۹ بررسی را گذراند؛ اجرای واقعی نصاب Windows باید روی دستگاه مقصد تأیید شود.

## نسخه 1.4.10 — بازبینی سازگاری Windows 10/11 x64 (۱۴۰۵/۰۸/۱۶)

- پیش‌نیازهای Windows 10 نسخهٔ 1809 به بالا و Windows 11 x64 صریحاً بررسی می‌شوند؛ Windows Server و PowerShell قدیمی‌تر از 5.1 با پیام روشن رد می‌شوند.
- آزمون اتصال registry به endpoint سبک `/-/ping` تغییر کرد تا proxyهایی که درخواست HEAD را رد می‌کنند، نصب آنلاین را بی‌دلیل متوقف نکنند.
- آرشیوهای Node/npm و SHA-512 ثبت‌شده مستقلاً بررسی شدند؛ مسیرهای `node.exe` و `npm-cli.js` در هر دو آرشیو موجودند.
- نصب واقعی Windows در این محیط Linux قابل اجرا نیست؛ بسته برای تست نهایی Windows 11 x64 و تأیید Windows 10 x64 آماده شده است.

## نسخه 1.4.9 — ترمیم مسیر npm در Windows (۱۴۰۵/۰۸/۱۶)

- کپی npm با robocopy به ساختار مورد انتظار `runtime\npm\package` انجام می‌شود و وجود `npm-cli.js` پیش از نصب وابستگی‌ها کنترل می‌شود.
- اگر Node.js دقیق از قبل موجود باشد ولی npm ناقص باشد، فقط npm ترمیم می‌شود و Node دوباره دریافت/جایگزین نمی‌شود.

## نسخه 1.4.8 — اصلاح BAT و ثبت گزارش تشخیصی نصب (۱۴۰۵/۰۸/۱۶)

- متن BATها کاملاً ASCII شد تا CMD ویندوز متن فارسی را به‌عنوان فرمان خراب اجرا نکند؛ نمایش فارسی فقط داخل PowerShell با فایل‌های UTF-8 دارای BOM انجام می‌شود.
- نصاب خطاهای اجرایی را همراه با موقعیت و stack در `%TEMP%\Pumpstation-install-error.log` ذخیره می‌کند؛ خطاهای parser که پیش از شروع اسکریپت رخ دهند نیز از BAT به همان گزارش افزوده می‌شوند.
- خطاهای اجرای میانبر/BAT در `%TEMP%\Pumpstation-launch-error.log` ثبت می‌شوند؛ برای خطای آماده‌نشدن سرور، `launch-failure.txt` و `server-error-*.log` نیز ساخته می‌شوند.

## نسخه 1.4.7 — حذف کاتالوگ و پایدارسازی نصب Windows (۱۴۰۵/۰۸/۱۶)

- رابط و endpointهای مدیریت کاتالوگ/دیتاشیت تجهیزات حذف شدند؛ قالب‌های backup قدیمی و جدول legacy برای بازیابی سازگاری خود را حفظ می‌کنند.
- installer و launcher برای نمایش بهتر فارسی، reuse نسخهٔ دقیق Node/npm و راه‌اندازی روی پورت آزادتر اصلاح شدند؛ هنگام خطا، مسیر و بخشی از لاگ‌ها نشان داده می‌شود.
- پس از seed موفق، فایل متنی موقت PIN حذف می‌شود؛ آینه می‌تواند روی volume جدا انتخاب شود و هم‌حجمی آینه/بک‌آپ در پنل هشدار داده می‌شود.
- آینه‌سازی، محتوای واقعی bundle مقصد را با checksumهای manifest بررسی می‌کند، نه فقط متن manifest را.
- PostCSS به نسخهٔ وصله‌شده ارتقا یافت، ابزار dev بلااستفاده حذف و override امن minimatch ثبت شد؛ `npm audit` بدون یافته است.
- راهنمای Windows شامل لینک مستقیم runtimeها و فهرست dependencyهای مستقیم شد.
- آزمون Windows واقعی در این نسخه اجرا نشده؛ نصب باید روی Windows 10/11 x64 تمیز اعتبارسنجی شود.

> هر مورد: چه خواسته شد → چه انجام شد → کجا. موارد ⏳ یعنی ساختار آماده و منتظر اطلاعات کارفرماست.

## نسخه 1.4.6 — ایمن‌سازی نصب production و شفافیت بازیابی (۱۴۰۵/۰۸/۱۵)

1. production اگر روستر محلی وجود نداشته باشد، حتی اگر فایل محلی PIN نمونه داشته باشد، یا دیتابیسِ قبلی هنوز PIN نمونه داشته باشد، پیش از سرویس‌دهی متوقف می‌شود. `ALLOW_SAMPLE_ROSTER=1` فقط برای آزمون/بازیابی کنترل‌شده است.
2. نصب تازهٔ production دیگر قرائت، هشدار، یادداشت یا وضعیت/ساعت ساختگی موتور درج نمی‌کند؛ وضعیت موتور «بررسی‌نشده» است تا اپراتور آن را تعیین کند. داده‌های موجود دست‌کاری یا پاک نمی‌شوند.
3. PINهای نمایشی ثابت از صفحهٔ ورود حذف شدند و import روستر نمونه از ماژول مشترکِ UI خارج شد.
4. بک‌آپ‌های JSON بیرون‌دستگاهی توکن کانال ربات را خالی می‌کنند؛ هنگام بازیابی، توکن محلی فقط برای همان کانال/مقصد حفظ می‌شود، وگرنه هشدار ورود دوباره داده می‌شود.
5. بک‌آپِ کاتالوگ‌های قدیمیِ embed شده حفظ می‌شود؛ پس از بازیابی، نبودن فایل PDF جداگانه یا ناسازگاری SHA-256 به‌صورت هشدار فهرست می‌شود. این هشدار بازیابی خود فایل PDF نیست.
6. audit6 هر جدول schema و فهرست `SERIAL_TABLES` را با طرح واقعی تطبیق می‌دهد؛ نسخهٔ UI از `package.json` خوانده می‌شود و تست‌های مرزی جلالی به `npm test` افزوده شدند.
7. فرمان جداگانهٔ StackBlitz پیش از bind روی `0.0.0.0` هشدار فارسی برجسته می‌دهد؛ فرمان پیش‌فرض ایستگاه همچنان loopback است.
8. گیت نصب تازه production با روستر محلی و بدون دادهٔ نمایشی آزموده می‌شود.
9. حذف خودکار بک‌آپ JSON، آینه و دامپ PostgreSQL خاموش شد؛ فهرست فایل‌های بک‌آپ در پنل همهٔ نسخه‌ها را نشان می‌دهد. پاک‌سازی فقط دستی است و فضای دیسک باید پایش شود.
10. پنل و Runbook محدودیت بک‌آپ JSON را روشن می‌گویند؛ بستهٔ بازیابی جداگانه، جدول‌های آرشیو، PDFها و فایل‌های سرد را با manifest و checksum نگه می‌دارد.
11. ساخت/آزمون/بازیابی بستهٔ بازیابی به پنل ادمین افزوده شد؛ خروج و ورود دادهٔ جدول‌ها جریانی است و پیش از restore بستهٔ ایمنی ساخته می‌شود.
12. آینهٔ خودکار علاوه بر JSON، آخرین بستهٔ بازیابی را نیز کپی و فایل‌های آن را راستی‌آزمایی می‌کند.
13. شکست ذخیره‌سازی راز نشست دیگر خاموش نمی‌ماند: خطای برجسته ثبت می‌شود و `/api/health?full=1` موقتی‌بودن راز را گزارش می‌کند.
14. گزارش سلامت کامل وضعیت روستر `local/sample` را نشان می‌دهد و هنگام استفاده از نمونه هشدار می‌دهد؛ هشدار لاگ نمونه نیز فقط یک‌بار چاپ می‌شود.
15. بایند مستقیم شبکه‌ای بدون پروکسی مورداعتماد، حتی با `LAN_ALLOW` خالی، دربارهٔ IP مشترک و محدودیت‌های per-IP هشدار می‌دهد.
16. `audit/conc.mjs` حالا سرویس هم‌زمان دو موتور متفاوت و سلامت زنجیرهٔ فعالیت را می‌آزماید و به `npm test` افزوده شد.
17. آزمون PostgreSQL واقعی، race درج توتال روزانه و ترتیب زنجیرهٔ هش فعالیت را آشکار کرد؛ قفل‌های advisory تراکنشی برای سریال‌سازی این دو مسیر افزوده شدند.
18. تیترهای تزئینی از بدنهٔ `CODE_ALL_FA.txt` حذف و استخراج‌گر سخت‌گیرتر شد تا محتوای فایل‌های استخراجی دقیق بماند.
19. ثبت تاریخ شمسی آینده در API رد می‌شود؛ خطاهای مجوز با وضعیت ۴۰۳ و خطاهای ورودی با وضعیت ۴۰۰ برمی‌گردند، و PIN ادمین ۴ تا ۶ رقم است.
20. هشدار باز برای هر سلول موتور/پارامتر/روز با upsert اتمیک یکتا می‌شود؛ مهاجرت `0006_alerts_open_unique.sql` رکوردهای باز تکراری را می‌بندد و تاریخچه را نگه می‌دارد.
21. بک‌آپ JSON خارجی و بستهٔ بازیابی دیگر secret یا کدهای TOTP را صادر نمی‌کنند؛ restore، TOTP دستگاه مقصد را حفظ می‌کند و نبود checksum برای JSON رد می‌شود مگر با تأیید صریح force.
22. گزارش روزانه وضعیت موتور را از تاریخچهٔ تغییر وضعیت تا پایان روز بازسازی می‌کند، نه از وضعیت فعلی.
23. فایل آرشیو ناقص در شکست نوشتن/ثبت پاک می‌شود؛ فایل سردِ مفقود در بستهٔ بازیابی هشدار می‌دهد و restore ناقص به تأیید صریح نیاز دارد.
24. پنل کانال‌ها امکان پاک‌کردن توکن را دارد؛ خروج از سایر نشست‌ها به نشست‌های ادمین محدود شده و خروج سراسری تأیید جدا می‌خواهد.
25. گیت نصب تازه اکنون مهاجرت 0006، build، ۳۰۰ آزمون و بازیابی بین دو نصب را بررسی می‌کند.

## نسخه 1.4 — فاز ۴: امنیت انتقال، آینهٔ بک‌آپ، ورود دوعاملی، مسیر PostgreSQL (۱۴۰۵/۰۸/۱۳)

> هدف فاز: بستن شکاف‌های «حمل داده روی شبکه»، «از دست رفتن دستگاه اصلی»، «سرقت PIN» و
> «وابستگی به یک نوع دیتابیس». هر مورد با آزمون خودکار سنجیده شده است.

### ورود دوعاملی (TOTP) — کد در `src/lib/totp.ts`
1. راز TOTP بدون هیچ کتابخانهٔ بیرونی (WebCrypto/Node `crypto`): SHA-1، گام ۳۰ ثانیه، ۶ رقم،
   پنجرهٔ ±۱ گام (تحمل انحراف ساعت ۳۰ ثانیه). `generateTotpSecret`, `totpCode`, `verifyTotp`, `otpauthUrl`.
2. ستون‌های `shifts.totp_secret / totp_pending / totp_enabled / totp_backup_codes / totp_enabled_at`
   (مهاجرت `0003_two_factor.sql`). راز فقط با دسترسی به دیتابیس خوانده می‌شود؛ در پاسخ API فقط
   یک‌بار در مرحلهٔ راه‌اندازی برمی‌گردد.
3. جریان ورود: `POST /api/auth` با `{key, pin, totp?}`. اگر دوعاملی فعال باشد و کد نیامده باشد →
   `401 {needsTotp:true}`؛ کد نادرست → همان قفل تدریجی ورود (بعد از چند تلاش `429`).
4. **کدهای پشتیبان**: ۱۰ کد `XXXX-XXXX` یک‌بارمصرف، ذخیره‌شده به‌صورت هش scrypt (همان `hashPin`)،
   مقایسه با زمان ثابت، حذف پس از مصرف + رویداد امنیتی `totp_backup_used`. ورودی کاربر
   حروف کوچک/خط تیره را هم می‌پذیرد (`normalizeBackupCode`).
5. اکشن‌های مدیریتی: `totp.status`, `totp.begin`, `totp.enable`, `totp.disable`, `totp.codes`.
   غیرفعال‌سازی و صدور مجدد، **تأیید هویت دوباره با PIN** می‌خواهد؛ ادمین برای «گوشی گم‌شده»
   می‌تواند دوعاملی شیفت دیگر را با PIN خودش بازنشانی کند.
6. رابط کاربری: مرحلهٔ دوم در صفحهٔ ورود (`Login.tsx`) با پیام «اگر گوشی در دسترس نیست از کد
   پشتیبان استفاده کنید»؛ پنل «ورود دوعاملی» در تب مدیریت (`TwoFactorPanel.tsx`) با نمایش کلید
   Base32، نشانی `otpauth://`، تأیید کد، نمایش یک‌بار کدهای پشتیبان + کپی/ذخیرهٔ فایل.

### آینهٔ بک‌آپ (کپی روی حافظهٔ بیرونی) — `src/lib/mirror.ts`
7. هر بک‌آپ فایلی می‌تواند بلافاصله روی رسانهٔ دوم (`MIRROR_DIR`: فلش، درایو USB، پوشهٔ شبکه)
   کپی شود؛ صحت کپی با **مقایسهٔ sha256 مبدأ و مقصد** تأیید می‌شود و فایل `.sha256` هم همراه می‌رود.
8. هر اجرا در جدول `backup_mirror_runs` (`at, ts, file, target, bytes, ok, error` + ایندکس زمانی)
   ثبت می‌شود؛ نگه‌داری ۳۰ نسخهٔ آخر (`MIRROR_KEEP`). اجراها **سریالی** می‌شوند تا دو درخواست
   هم‌زمان، فایل هم‌نام و هش ناسازگار نسازند.
9. تازه‌سازی خودکار: `ensureMirrorFresh` در هر عملیات (حداکثر هر نیم‌ساعت یک بررسی) و اگر آخرین
   کپی سالم قدیمی‌تر از `MIRROR_STALE_HOURS` (پیش‌فرض ۳۰ ساعت) باشد، نسخهٔ تازه می‌سازد و کپی می‌کند.
10. مسیر API: `GET/POST /api/mirror`. POST هم با نشست ادمین کار می‌کند و هم با هدر `x-mirror-token`
    (توکن محلی خودساخته در `.data/mirror-token` با دسترسی 600) برای Task Scheduler بدون مرورگر.
11. اسکریپت زمان‌بند `scripts/mirror-backup.mjs` (کد خروج ۰/۱ + لاگ در `.data/logs/mirror.log`).
12. پنل «آینهٔ بک‌آپ» در تب مدیریت (`MirrorPanel.tsx`): حکم سلامت (سالم/قدیمی/رسانه وصل نیست/خطا)،
    مسیر، آخرین کپی، تعداد ۲۴ ساعت، فهرست نسخه‌ها، دکمهٔ «بک‌آپ تازه + کپی» و «کپی آخرین نسخه».
13. `/api/health?full=1` حالا وضعیت آینه را هم گزارش و در صورت کهنگی هشدار می‌دهد.
14. مهاجرت `0004_mirror_ts.sql`: ستون `ts` (زمان یونیکس) برای مرتب‌سازی درست سابقهٔ آینه.

### HTTPS و هدرها

- ساخت پیش‌نمایش اجرایی Next.js + PostgreSQL با تم تیره: ورود PIN، داشبورد، کارت موتور/پمپ متحرک، تجهیزات جانبی (انتقال نوار ایمنی)، رجیستری، گزارش PDF، بک‌آپ/بازیابی، سابقهٔ تغییر مقادیر، رفع پرش دکمهٔ بازگشت.
