# شبکهٔ ایستگاه: اتصال اتاق دوم (نسخهٔ ۱٫۴٫۱)

> سناریو: دو اتاق نزدیک هم؛ سرور در اتاق ۱، مرورگر اپراتور در اتاق ۲.
> قانون قفل‌شده: پیش‌فرض فقط `127.0.0.1` است؛ حالت شبکه فقط با پیکربندی
> صریح (`BIND=lan` یا `‎--host`) فعال می‌شود.
>
> **نقشهٔ شما:** اتاق ۱ = اتاق کنترل **بالا** (سرور، مرجع، محل ذخیرهٔ اطلاعات)؛
> اتاق ۲ = اتاق کنترل **پایین** (فقط مرورگر، فقط ثبت اطلاعات). برنامه فقط روی
> سیستم بالا نصب می‌شود؛ سیستم پایین فقط مرورگر باز می‌کند. ورود در پایین با
> PIN شیفت (اپراتور) و در بالا با PIN ادمین؛ چون هر دو به یک دیتابیس وصل‌اند،
> هر ثبتی در پایین همان لحظه در بالا هم هست (نمایش با رفرش بعدی صفحه).

---

## ۱. نقشهٔ پیشنهادی (الف — امن)

```
اتاق ۲ (مرورگر) ──https──▶ اتاق ۱: Caddy (‎:443) ──http──▶ اپ (127.0.0.1:3000)
```

- اپ روی **حلقه** می‌ماند؛ فقط Caddy روی شبکه باز است.
- Caddy هدر IP را **بازنویسی کامل** می‌کند (`deploy/Caddyfile`) تا هدر جعلی
  کلاینت به اپ نرسد.
- در `.env.local` سرور اپ:

```
TRUST_PROXY=1
LAN_ALLOW=192.168.1.0/24
```

(به‌جای `192.168.1.0/24` رنج واقعی اداره را بگذارید؛ با کاما چند رنج مجاز است.)

## ۲. حالت ساده (ب — بدون پروکسی)

اگر Caddy نصب نکرده‌اید، اپ را مستقیم روی شبکه باز کنید:

```powershell
npm run preview:lan
```

یا `BIND=lan` در `.env.local`. در این حالت:

- اپ **IP واقعی را نمی‌بیند** (محدودیت فنی)؛ پس `LAN_ALLOW` در اپ اعمال
  **نمی‌شود** و کنترل دسترسی فقط با **فایروال ویندوز** است (بخش ۴).
- `TRUST_PROXY` را `1` **نکنید** (پروکسی‌ای در کار نیست که هدر را بشوید).

## ۳. جدول تصمیم

| حالت | BIND | TRUST_PROXY | LAN_ALLOW | کنترل IP |
|---|---|---|---|---|
| تک‌دستگاهی (پیش‌فرض) | خالی | 0 | خالی | لازم نیست |
| دو اتاق + Caddy (پیشنهادی) | خالی | 1 | رنج اداره | اپ + فایروال |
| دو اتاق بدون پروکسی | lan | 0 | خالی | فقط فایروال |

> اگر `LAN_ALLOW` تنظیم شود ولی `TRUST_PROXY=1` نباشد، سرور هنگام بالا
> آمدن اخطار می‌دهد که فهرست مجاز اعمال نمی‌شود.

## ۴. فایروال ویندوز (هر دو حالت)

1. پورت `3000` از شبکه **بسته** باشد (فقط خودِ دستگاه).
2. فقط در حالت الف: پورت `443` فقط برای رنج اداره باز باشد:

```powershell
New-NetFirewallRule -DisplayName "pumpstation-https" -Direction Inbound `
  -Protocol TCP -LocalPort 443 -RemoteAddress 192.168.1.0/24 -Action Allow
```

## ۵. آینهٔ روزانه به حافظهٔ بیرونی

در Task Scheduler ویندوز، هر شب ساعت ۲:

```
node C:\pumpstation\scripts\mirror-backup.mjs
```

(با `MIRROR_DIR` روی فلش/درایو بیرونی در `.env.local`.) سامانه هر روز در
داشبورد نشان می‌دهد آینه چند ساعت پیش به‌روز شده و اگر از
`MIRROR_STALE_HOURS` بگذرد، بنر هشدار می‌دهد.

## ۶. آزمون اتصال از اتاق ۲

1. از مرورگر اتاق ۲ آدرس سرور را باز کنید (`https://192.168.1.50` در حالت
   الف یا `http://192.168.1.50:3000` در حالت ب).
2. ورود با PIN، ثبت یک مقدار آزمایشی، و بررسی داشبورد.
3. از یک دستگاه **خارج از رنج** (مثلاً با IP دستی دیگر) تلاش کنید؛ در حالت
   الف باید خطای «اتصال از این شبکه مجاز نیست» بگیرید.

## ۷. عیب‌یابی

| علامت | علت محتمل | راه‌حل |
|---|---|---|
| صفحه باز نمی‌شود | فایروال / IP اشتباه | `ping` سرور؛ قانون فایروال؛ `ipconfig` |
| خطای «شبکه مجاز نیست» برای همه | `LAN_ALLOW` اشتباه | رنج اداره را اصلاح کنید و ری‌استارت |
| ورود انجام ولی API رد می‌شود | ساعت/کوکی | ساعت هر دو دستگاه؛ کش مرورگر |
| گواهی نامعتبر (حالت الف) | ریشهٔ Caddy نصب نشده | `root.crt` را طبق DEPLOY_HTTPS نصب کنید |

## ۸. نتایج آزمون توسعه‌دهنده (۱٫۴٫۱)

- بایند پیش‌فرض فقط `127.0.0.1` (بررسی با `ss`)؛ `‎--host lan` روی
  `0.0.0.0` با اخطار فایروال بالا می‌آید.
- با `TRUST_PROXY=1` و `LAN_ALLOW=10.9.9.0/24`: هدر داخل رنج → ‏200، هدر
  خارج رنج → ‏403 با کد `lan_denied` (هم API هم صفحهٔ اصلی).
- در حالت پیش‌فرض، هدر IP جعلی نادیده گرفته می‌شود (ورود با هدر جعلی سالم
  انجام شد و نشست مسموم نشد).
- هر ۵ مجموعهٔ آزمون خودکار (۱۴۰ تست) پس از تغییرات سبز است.
