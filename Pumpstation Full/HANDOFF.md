# HANDOFF — پروژه «پمپاژ زیرزمینی» 🔄
> **این فایل برای هر هوش مصنوعی / توسعه‌دهنده‌ای است که قرار است ادامه کار را بدهد. تا انتها بخوان.**

---

## ۱) پروژه چیست؟

سامانه وب برای ثبت و پایش تجهیزات یک **پمپاژخانه زیرزمینی آب** (ایران). کاربر نهایی، اپراتورهای شیفتی هستند و سطح آشنایی کارفرما با برنامه‌نویسی **صفر** است — همه‌چیز باید ساده و قابل استفاده با موبایل/کامپیوتر باشد.

**زبان رابط کاربری: فارسی (RTL). تمام تاریخ‌ها شمسی با فرمت `1404/08/09` (اعداد لاتین مثل 1405/08/09).**

## ۲) تکنولوژی و نحوه اجرا

- **بک‌اند:** Flask (پایتون) + SQLite — تک‌فایل `app.py`
- **فرانت‌اند:** HTML/JS/CSS خام (بدون فریمورک) + Chart.js نسخه لوکال + فونت وزیرمتن لوکال
- **کتابخانه تاریخ شمسی:** `jdatetime` (pip install --user jdatetime)
- **دیتابیس:** `pumpstation.db` (در صورت نبود، خودکار ساخته و seed می‌شود)
- **اجرا:** `cd pumpstation && python3 app.py` → پورت 8000
- **نصب پیش‌نیازها:** `pip install --user flask jdatetime pandas openpyxl`
- فلدر پروژه: `pumpstation/` (باید همین ساختار حفظ شود)

## ۳) ساختار فایل‌ها

```

    ├── plc.html/plc.js            # ایمپورت اکسل PLC + نمودار ترند
    ├── equipment.html/equipment.js # پرونده تجهیزات (پلاک/کاتالوگ/اوردر + تاریخچه)
```

## ۴) دیتابیس (جداول اصلی)

```
equipment:      id, tag, name, category(pump/motor/transformer/panel/valve/instrument/other),
                spec, pm_interval_days, location, qty,
                manufacturer, plate, catalog_no, order_no, notes   ← فیلدهای پرونده
readings:       id, equipment_id, date(jalali), time, temp, current, voltage, hours, pressure, note, operator
maintenance:    id, equipment_id, date(jalali), type(PM/repair/...), description, operator
users:          id, name, shift(A/B/C), pin(پیش‌فرض 1234), role
schedule:       id, user_id, date(jalali), type(leave/swap), replacement_id, note
plc_data:       id, tag, ts, temp, current, voltage, pressure   ← ذخیره‌ی «دقیقه‌ای» (میانگین از ثانیه‌ای)
daily_log:      id, date(jalali), shift, operator, pumps_on("P-01,P-03"),
                flow, total_flow, suction, discharge, tank_inlet, surge_tank1, surge_tank2,
                utility, cooling, note
```

**تجهیزات seed شده (۱۷۵ قلم از اکسل ۵ شیت کارفرما):** موتورهای MV زیمنس 1800kW/6.6kV به تفکیک (EM-01..EM-08)، پمپ‌های ۱ تا ۸ (P-01..P-08)، کمپرسورهای سرچ‌تانک (CMP-1/2)، پمپ‌های تاسیسات (HP-11/12، CP-13/14، CTP-15/16، MKP-19، FP-1/2...)، فن‌ها (F-1..F-4)، پمپ‌های سامپ (SMP-1..4)، ترانس‌ها (TR-1/2، TR-D، TR-A1/2)، دیزل‌ژنراتورها (DG-1/2)، ۷۱ شیرآلات (V-001..V-071)، ۲۹ تابلو (تگ واقعی مثل INCOMING_A, BUSVT, PLC_400H, UPS...)، ابزار دقیق (IN-001..012)، سایر (OT-001..).

## ۵) API ها (همه JSON)

| مسیر | توضیح |
|---|---|
| `POST /api/login {user_id,pin}` / `POST /api/logout` / `GET /api/me` | ورود اپراتور (session) |
| `GET /api/users` | لیست اپراتورها |
| `GET /api/equipment?q=&category=` | لیست تجهیزات + جستجو |
| `GET /api/equipment/<id>` | پرونده کامل تجهیز + maintenance + readings |
| `PUT /api/equipment/<id>` | ویرایش پلاک/کاتالوگ/اوردر/نوتز/اسپک/لوکیشن |
| `GET/POST/DELETE /api/readings` | ثبت پارامتر لحظه‌ای تجهیز |
| `GET/POST/DELETE /api/maintenance` | ثبت PM و تعمیرات |
| `GET/POST/DELETE /api/daily` | گزارش روزانه شیفت |
| `GET /api/daily/monthly?jyear=&jmonth=` | جدول دبی روزانه ۱ تا آخر ماه شمسی + تجمعی + جمع کل (اتوماتیک طول ماه/کبیسه اسفند) |
| `POST /api/plc/import` (multipart: file,tag) | ایمپورت اکسل/CSV خروجی PLC — ستون‌های زمان/دما/جریان/ولتاژ/فشار خودکار تشخیص داده می‌شوند؛ داده ثانیه‌ای → **میانگین دقیقه‌ای** ذخیره می‌شود (تست شده: 86,400 ردیف → 1,440) |
| `GET /api/plc?granularity=minute|hour|day&hours=&tag=` | دیتای نمودار ترند |
| `GET /api/dashboard` | آمار: counts, stats, last_readings, pm_due, today(jalali) |
| `GET /api/report?jyear=&jmonth=` | گزارش ماهانه شمسی |
| `GET /api/backup` | دانلود بک‌آپ دیتابیس |
| `POST /api/demo` / `DELETE /api/demo` | ساخت/حذف داده نمونه |

## ۶) قواعد کاری و توافق‌های کارفرما (مهم! رعایت شود)

1. **لینک پیش‌نمایش زنده فقط وقتی کارفرما صریحاً بگوید** نمایش/ساخته شود (نه با هر تغییر کوچک).
2. **فایل zip فقط وقتی خودش بخواهد** ساخته و تحویل شود.
3. تاریخ‌ها همیشه شمسی `YYYY/MM/DD`؛ ورودی تاریخ در فرم‌ها `type=text` نه `type=date` (چون میلادی می‌شود).
4. فونت و Chart.js باید **لوکال** باشند (فیلترینگ/تحریم ایران).
5. کارفرما صفر مطلق برنامه‌نویسی است؛ توضیح‌ها ساده و عملی باشند.
6. سبک رنگی فعلی: سبز تیره/teal (#16606b) + نارنجی تاکیدی + کارت‌های سفید روی پس‌زمینه خاکستری روشن. ساده و مهندسی نگه داشته شود.
7. دکمه چاپ باید در همه صفحات گزارش‌محور کار کند (استایل @media print در style.css هست).

## ۷) وضعیت فعلی — چه چیزی ساخته و تست شده؟

- ✅ همه صفحات بالا ساخته و با سرور اجرا شده‌اند
- ✅ ورود اپراتور با PIN (پیش‌فرض 1234)، نوار کاربر در همه صفحات
- ✅ ایمپورت PLC با میانگین‌گیری دقیقه‌ای + نمودار ترند با تفکیک دقیقه/ساعت/روز — تست موفق
- ✅ گزارش روزانه شیفت با همه فیلدها (پمپ‌های روشن، دبی، مکش/رانش، مخزن ورودی، سرچ‌تانک‌ها، تاسیسات، خنک‌کاری) — تست موفق
- ✅ جدول دبی ماهانه با تجمعی — تست موفق
- ✅ پرونده تجهیزات با جستجو و ویرایش پلاک/کاتالوگ — تست موفق
- ✅ داشبورد با KPIهای: تعداد تجهیزات، رکوردها، تعمیرات، PM عقب‌افتاده، دبی امروز، شیفت امروز + نمودارهای روند دما/جریان/ولتاژ/دبی ماه
- ✅ گزارش ماهانه شمسی، تعمیرات/PM، شیفت‌ها (کاربران + مرخصی/جابجایی + وضعیت امروز)

## ۸) کارهای باقی‌مانده (اولویت بعدی)

1. **فرم گزارش روزانه کاغذی واقعی:** کارفرما فرمت کاغذی فعلی پمپاژخانه را می‌فرستد → فرم daily باید دقیقاً مطابق آن بازطراحی شود (فیلدها/ترتیب/عنوان‌ها).
2. **پلاک‌ها و مشخصات واقعی:** کارفرما پلاک/کاتالوگ/اوردرنامبر و شماتیک با تگ‌های واقعی منطقه‌به‌منطقه می‌دهد → در پرونده هر تجهیز (PUT /api/equipment/<id>) وارد شود؛ در صورت مغایرت تگ‌های فعلی با تگ واقعی، اصلاح شود.
3. **نمونه فایل اکسل واقعی خروجی PLC** کارفرما → تنظیم دقیق تشخیص ستون‌های ایمپورت.
4. **سوابق PM اولیه و تاریخچه خرابی هر تجهیز** → تا نوبت‌های PM واقعی محاسبه شود (الان همه «بدون سابقه» هستند).
5. ایده‌های کارفرما برای آینده: هشدار دمای بالا، لیست قطعات یدکی، تغییر PIN توسط کاربر، نسخه تک‌فایلی آفلاین.

## ۹) راه‌اندازی سریع (چک‌لیست)

```bash
pip install --user flask jdatetime pandas openpyxl
cd pumpstation
python3 app.py            # سرور روی پورت 8000 بالا می‌آید
curl localhost:8000/api/dashboard   # باید JSON برگرداند
```
- اگر دیتابیس نبود، خودکار از equipment_seed.json ساخته می‌شود (۱۷۵ تجهیز).
- اپراتورها با PIN پیش‌فرض (حریم خصوصی: نام واقعی از سند عمومی حذف شد؛ نام‌ها فقط در فایل محلی ایستگاه).
- برای اسکرین‌شات/بازبینی: Playwright با `--no-sandbox` و proxy={"server": os.environ["http_proxy"], "bypass": "localhost,127.0.0.1"}.

## ۱۰) نکته مهم برای هوش مصنوعی بعدی

- قبل از هر تغییر اساسی، **از app.py و دیتابیس بک‌آپ بگیر**.
- قواعد بخش ۶ را حتماً رعایت کن؛ کارفرما به ترتیب و قول پایبند است.
- اگر فایل یا اطلاعاتی (فرم کاغذی، پلاک‌ها، اکسل PLC) هنوز داده نشده، از کارفرما بخواه همان را بفرستد؛ خودت حدس نزن.
- فارسی درست بنویس: نیم‌فاصله صحیح («می‌شود»، «تجهیزها» نه «تجهیزها» چسبیده بدون نیم‌فاصله).
